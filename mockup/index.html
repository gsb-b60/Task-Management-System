Colour language

There is no brand primary colour. Blue appears only for links, focus rings, the active nav item and checkbox selection — nothing more. Every status signal is a soft tint plus an icon or a text label, so meaning never depends on colour alone (SRS §8, Phase 07 §8).

Green — done / open / success
DONE status, open GitHub issue, save confirmed, delete toast
Purple — in progress
IN_PROGRESS status, roadmap active bar
Amber — warning / due soon
MEDIUM priority, due within 3 days, GitHub rate limit
Red — error / overdue / closed
isOverdue, HIGH priority, closed issue, validation errors
Grey — TODO / low priority
TODO status, LOW priority, disabled controls
Blue — affordance only
Links, focus ring, active nav, checked checkbox

Mockup conventions

Per-screen anatomy
  • Meta bar — ID, name, flow breadcrumb, device list.
  • State blocks — one labelled block per state, data-grounded.
  • Device frames — Desktop 1440, Tablet 834, Phone 390.
Data discipline
  • isOverdue and daysUntilDue render verbatim from the server; never recomputed from a client clock (Phase 06 §4.1).
  • Absent status keys render 0, never blank.
  • Due labels: 0 → "due today", negative → "overdue by N days", positive → "in N days".
  • 401 is a normal state, not a surfaced error.
